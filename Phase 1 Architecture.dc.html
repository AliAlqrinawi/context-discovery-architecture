Context Discovery · Phase 1
production architecture

One deterministic command — diff in, context bundle out — that performs only the discovery moves Phase 0 proved, attaches a reason and a lever to every item, and enforces a token budget with a visible drop list. It does not review, judge, score, or call a model.

Full written architecture: architecture/README.md — verification, modules, interfaces, structure, diagrams, traceability, acceptance, and nine ADRs.

01

Verification of the validated research

The project

A documented validation effort, not a shipped product: can intelligently selected project context produce a better AI code review than a raw Git diff, while using significantly less context than the whole repository? Framed permanently as three conditions — A diff only, B diff + whole repo (yardstick, never the product), C diff + targeted bundle.

The hypothesis — status: open

Phase 0 validated answer keys, not review outcomes. It proved the classification method discriminates, produced a bounded catalogue of discovery moves, established the two-lever cost model, and disproved forward import-following. The A/B/C runs were never executed and scored, so the central claim that context improves a review remains untested.

02

The architecture

One process, one command, nine ordered stages — a batch transformation, not a service. A pure pipeline behind ports: a thin CLI shell, one use case, pure discovery logic, and adapters that are the only code touching the filesystem, composer.json, PHP source text, or the output stream.

Inside the boundary

Diff parsing · assertion extraction · the lever decision · depth-one resolution and member slicing · bounded caller grep · assumption text · bundle assembly, token accounting, budget drops · two serialisations.

Consumed, never owned

Git (the diff arrives as text; the tool never invokes it) · the target repository, read-only on local disk · the PSR-4 autoload map. All reads are scoped inside --repo; an escape or unreadable path becomes a flag.

Downstream, deliberately absent

The reviewer model, the prompt, the A-vs-C scoring, and every server, queue, daemon, watcher or hook. There is no runtime beyond the command.

Public contract — the bundle

{
  "bundle_version": 1,
  "budget_tokens": 8000,
  "used_tokens": 2143,
  "items": [
    { "lever": "fetched",
      "reason": "changed call site depends on PlaidAccount::forItem() and official_name",
      "assertion_kind": "named_reference",
      "provenance": { "path": "app/Models/PlaidAccount.php", "member": "forItem", "lines": [41, 58] },
      "payload": "<minimal slice>", "tokens": 180 },
    { "lever": "flagged",
      "reason": "reconciliation assumes a surrounding DB transaction; caller not verified",
      "assertion_kind": "unverifiable_premise",
      "provenance": { "path": "app/Services/Plaid/PlaidAccountService.php", "lines": [120, 168] },
      "payload": "ASSUMPTION: this code assumes a surrounding transaction; caller not checked",
      "tokens": 14 }
  ],
  "dropped": [ { "reason": "route wiring for reauth endpoint", "note": "below budget priority" } ]
}

Item order is fixed so output is diffable: absence → same-file reference → changed signature → named reference → premise, then path, then member. assertion_kind exists so precision can later be measured per move. Port and collaborator signatures: 03-interfaces.md.

Domain boundaries

Diff — what changed. Assertion — what the change claims but cannot prove; the centre of gravity. Bundle — what the reviewer receives. Diff types never reference Assertion or Bundle types; Assertion carries a plain origin, not an object graph; Bundle carries plain provenance. No domain performs I/O, formatting, or token counting.

Dependency rules
1 · Dependencies point inward. Domain imports nothing. 2 · Discovery, Assembly and Pipeline see Ports only — never an adapter. 3 · Adapters see Ports and Domain only. 4 · Cli\Wiring is the one place a concrete adapter is named. 5 · No cycles, no singletons, no service locator, no runtime class discovery.
Naming

PHP 8.2, strict types, PSR-12. Interfaces named for the capability with no suffix; implementations carry the distinguishing qualifier. Vocabulary is the research repository's, verbatim — assertion, lever, fetched, flagged, reason, provenance, dropped, premise, slice. JSON fields are snake_case.

Forbidden names, because each signals scope escape: *Engine, *Agent, *Plugin, *EventBus, *Listener, *Cache, *Index, *Graph, *Score, *Severity, *Reviewer, *Client.

4.2 · Request flow — one invocation

01Cli\DiscoverCommandValidate argv. --budget missing → exit 1 with the reason.
02UnifiedDiffParserDiff text → changed files, regions, changed member signatures.
03LocalSourceRepositoryLoad the full current text of each changed file — analysis input, not payload.
04AssertionExtractorFour extractors, fixed order → a deterministic list of assertions.
05LeverPolicyPer assertion: named + single + depth-one on disk → fetched; reverse-graph-deep, runtime or data-state → flagged.
06ResolversDispatched by an explicit match on assertion kind — no probing. Own-file · named reference · caller grep → minimal slices. An unreadable path or a truncated search falls through to a flag; a search that completes with zero results is a settled answer, not a flag.
07AssumptionWriterOne fixed statement per catalogue premise, with its reason and provenance.
08BundleAssembler → BudgetItems get reason, lever, provenance; over budget, the lowest-priority item is dropped and recorded.
09BundleWriterJSON or Markdown to stdout; diagnostics to stderr; exit 0.

No step calls the network, spawns a process, writes into the repository, or returns to an earlier step.

05

Architecture decision records

Nine new decisions. Each states why it exists, the Phase 0 evidence behind it, and the alternatives rejected. These are additions to — never revisions of — research ADR-001, ADR-002 and ADR-003. A002, A003, A006 and A007 carry amendments from the freeze reviews; A009 carries three — its trigger table (04), its flag-provenance claim (04), and its premise-membership rule (05).

A001
PHP 8.2 CLI, one command, zero runtime dependencies The spec's inputs are the PSR-4 map and PHP files, and all four experiments are Laravel/Plaid commits; a dependency-free CLI is the smallest thing satisfying "no index, no graph, no service to call". Evidence: implementation-spec inputs · Exp 1, 3, 4 · P8, P9  ·  Rejected: Python/Node core · language-agnostic adapters · Artisan command · hosted service · parser and console dependencies
A002
A pure pipeline behind ports — not events, not plugins, not agents The spec already fixes nine ordered responsibilities; values passed between pure stages make each one checkable against a key and the whole run byte-reproducible. Evidence: nine spec responsibilities · P5, P6, P8, P9  ·  Rejected: event bus (item provenance would depend on listener order) · plugin points · agent loop · god class · framework middleware
A003
The move set is closed: four extractors, three resolvers Experiment 4 added no new move, so the boundedness is expressed in code. If the unrun sloppy commit needs a move the four cannot express, the bundle shows the gap instead of absorbing it. Evidence: discovery-moves catalogue · Exp 4 "no new move" · ADR-003  ·  Rejected: plugin registry · config-driven rules · one generic extractor (loses per-move precision) · a fifth extractor for config now
A004
Slice members with PHP's built-in tokenizer — no AST library, no regex Every minimum-context list is member-level ("one method", "one small class"), and the missing-import finding needs the use block as a structure. Evidence: Exp 1, 4 minimum-context lists · spec "not a whole file" · P8, P9  ·  Rejected: php-parser AST · regex parsing · whole-file fetch · a symbol index
A005
Full changed-file text is an analysis input; only slices enter the bundle R1's "load the full text" is easily misread as "emit the file". Emitting it would fail Experiment 2's near-empty expectation by construction. Evidence: Exp 2 "almost-empty bundle" · Exp 1 "one model and three method bodies" · spec precision criterion · P7  ·  Rejected: whole-file payloads · echoing the diff · configurable context radius
A006
Reverse-caller is a bounded in-process grep — not a graph, not a subprocess R3 says a crude grep over app/ suffices and a call graph is "not yet earned"; the deep up-the-stack question is flagged, never searched. Evidence: R3 · Exp 4 "a grep, not a file fetch" · fetch-vs-flag transaction example · ADR-002's ban on a maintained graph  ·  Rejected: call graph · shelling out to grep/rg · unbounded results · AST-accurate resolution
A007
A naive, documented token estimate — not a real tokenizer The cost criterion is coarse and comparative ("dramatically below B"); one documented characters-per-token constant is adequate and keeps the tool model-agnostic and offline. The ratio's value is recorded as an architectural assumption, not evidence — the standard A008 sets. Evidence: hypothesis cost wording · P7 · X5 · no optimisation before measurement  ·  Rejected: BPE library · remote tokenizer · byte/word counts · no accounting
A008
--budget is required and has no default The research states the budget only relative to a condition-B measurement that does not exist. A default would be a fabricated threshold shaping every later measurement from inside the code. Evidence: hypothesis "well under half of B's tokens" · requirements' ban on encoded assumptions · P7  ·  Rejected: a shipped default · size-derived heuristic · no budget · a config file
A009
Flags come from a closed premise catalogue, not from inference Six premises, each with one fixed sentence and one literal trigger — emitted if and only if that trigger fires, so no implementer invents a heuristic. Three statements come almost verbatim from the fetch-vs-flag examples, one covers schema, two cover resolution failures. A premise exists only where an unverified premise exists: a question the run settled yields none. The flag path is where judgement and an LLM would otherwise creep back in. Evidence: fetch-vs-flag statements · Exp 1, 3 · X3, X4, X5 · P6, P10  ·  Rejected: free-text flags · model-generated text · heuristic premise inference · a config resolver instead · dropping the concern
06

Acceptance — the bundle against the keys

The acceptance test is the spec's, not a new one: for all four Phase 0 commits, the bundle must reproduce that commit's minimum-context list — fetching the fetch-type items, flagging the flag-type ones — within budget. Fixtures are named experiment-0N to sit beside the research files.

experiment-01 · recall fetch-expected: use block + syncFromResponse (absence), upsertFromPlaid (same-file reference, band 2), the model surface (named reference, band 4). flag-satisfied: the caller — the transaction premise. No grep runs; no signature changed.
experiment-02 · precision Almost empty. Pulling the model "just in case" fails the test.
experiment-03 · flags flag-satisfied: cache-store, schema-index and trashed-data premises, each fired by its trigger. No config/migration resolver is invoked.
experiment-04 · callers fetch-expected: the createLinkToken slice, the enum, and call sites of reactivate( under app/ — a real signature change. No premise: this is the precision guard for the transaction trigger.

The four diffs are an operator-supplied prerequisite — the research repository contains no patch text, so this project ships only the expectation files and the harness fails loudly when a fixture diff is absent. Fabricating one would grade the tool against invented ground truth.

Every fixture also asserts determinism (two runs, byte-identical) and budget honesty (used ≤ budget, every omission listed in dropped). Recall and precision are reported as counts; the tool grades nothing. Details, unit-test list, and the first-run instruction — the sloppy Experiment 5 commit — in 06-acceptance.md.
